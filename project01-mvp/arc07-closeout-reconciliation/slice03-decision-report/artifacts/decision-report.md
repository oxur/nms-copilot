## Two design questions to settle before changing runtime behavior

**Map/live-update interaction — recommend a fixed snapshot, with live refresh optional.** `crates/nms-copilot/src/main.rs:267–278` holds a blocking model read guard throughout the modal map; `crates/nms-copilot/src/coordinator.rs:345–365` needs a blocking write guard to apply an update. A writer attempting acquisition while the map is open waits until the read guard is released. The actual wait duration and user impact were not measured. The smallest behavior proposal is to capture a fixed, read-only map snapshot on entry and release the shared read guard before the modal interaction, so the coordinator can apply/cache/publish while the map remains stable for that visit. Live map refresh is a separate optional UX choice, not a prerequisite for writer progress. Snapshot ownership and copy cost need Duncan’s review. If authorized, verify coordinator/cache/MCP progress during the open map, a stable map projection from the entry snapshot, and ordinary exit/restoration/continued REPL through the existing PTY route. Slice01 did not exercise a concurrent writer.

**New graph nodes and edges — retain the original requirement pending reconciliation.** `crates/nms-graph/src/model.rs:441–484, 685–805` states that inserted systems receive nodes but no edges and that `apply_delta`/`apply_save_update` do not rebuild edges. Original Project01 plan language promises graph edges for newly inserted systems; the current implementation/docs do not amend that promise. Keep the original requirement open while the route and caller composition is reconciled. Any decision to change that requirement needs an explicit Operator amendment. Do not change runtime behavior on this inventory alone. If implementation is later authorized, compare an incrementally updated route with a full-model rebuild using literal endpoints/ranges and verify cache reload preserves the chosen behavior (`crates/nms-graph/src/route.rs`, `crates/nms-cache/src/serialize.rs`, and the coordinator path).
