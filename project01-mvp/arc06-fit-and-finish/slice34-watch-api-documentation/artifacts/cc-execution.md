Watcher behavior comes from `watcher.rs:1–485`. `WatchConfig::default` is an empty path and 500 ms debounce; it is not an auto-discovered/usable save. All public start functions synchronously check path existence and parse the checked initial save before debouncer/watch/thread setup. The checked file parser's panic behavior is not converted to an `Err`/catch-unwind guarantee.

The watcher uses a non-recursive parent-directory watch and only accepts `Any` events whose path matches exactly or whose canonical paths match while both still exist. File stability is two equal size readings 100 ms apart, a heuristic rather than content validation or an atomic-write guarantee. Debouncing/backend coalescing means intermediate writes are not guaranteed as distinct events. Backend error batches are ignored. A successful parse resets the failure count and becomes the new baseline after processing; a failed parse does not advance baseline or emit an event. Exactly the fifth consecutive failure prints one warning to stderr; success resets the count, with no separate recovery message. Parse/name/update outputs are not saved to cache/model or user save.

`start_watching` uses an unbounded delta channel and sends only nonempty additive deltas; it sends no initial event and cannot report supported player state/version/name-only changes. Update and observation streams use capacity-one sync channels and can retain one additional parsed event in the worker while retrying every 10 ms. Updates emit when delta, complete supported player state, or source version changes. Observations additionally compare the complete explicit checked name map, including removals and explicit empty values. A missing name entry is not a clear instruction. These are parse observations, not complete raw JSON/save maps or lossless journals. The backend may coalesce writes. Owner drop removes the debouncer, requests cancellation, and joins the worker; queued events remain readable before disconnection only if the receiver is retained separately, while a pending event can be discarded. File I/O/parsing/backend teardown means no hard join deadline. Worker panic is not sent as an error; join logs a best-effort stderr warning. There is no explicit stop API or application cache-writer coordination guarantee.
