## Readback of source behavior and requested docs

**W1 — entrypoint and cleanup boundary (`mod.rs:23–42`).** `run_map` borrows `GalaxyModel` and `SessionState`, enables raw mode, enters the alternate screen and hides the cursor, constructs the terminal, runs the loop, then attempts raw-mode disable and screen/cursor restoration. A loop error still reaches cleanup. Failures during setup can return before cleanup; cleanup failure can replace the loop result and prevent later restoration; panics are not guarded by RAII. Thus the current “even if the loop errors” wording cannot be generalized into guaranteed restoration. The entry example should be `no_run`, use the actual map/session/model imports and `io::Result` with `?`, and state that an interactive terminal is required. The loop draws before handling the next event and exits after observing `should_quit` (`mod.rs:44–65`).

**W2 — input contract (`input.rs:8–35`, `38–71`).** `handle_input` polls for 100 ms, reads an event only when one is available, and propagates poll/read I/O errors. `MapAction::None` can mean timeout, ignored event, or an ordinary key mutation; it does not promise unchanged state. Resize carries width then height and applies `state.resize` before returning. Key event kind is not filtered. While help is open, any key first dismisses help and has no other key effect, including `q` and Ctrl-C; resize remains actionable. Otherwise arrows move, Enter/`+` zoom in, Esc/`-` zoom out and requests quit only when the zoom stack is empty, `q`/Ctrl-C request quit, unmodified lowercase `c` centers, and `?` toggles help. Input handling does not itself establish or restore terminal mode.

**W3 — state, projections, and numeric limits (`state.rs:8–281`).** The public fields are independently mutable; `MapState::new` initializes Galaxy zoom, session-position center when present (even if its address galaxy differs), otherwise player position then origin, a zero cursor, 78×19 grid, and empty/false flags. The model's active galaxy supplies the selected galaxy and filters base labels; `session.galaxy` does not select it. Player X/Z is copied without a galaxy comparison. Base labels are a snapshot: selected-galaxy bases sorted by case-sensitive name, capped at 26, then assigned A–Z with copied names and X/Z. Equal-name ordering is not promised when the source iteration is a hash map; later model changes do not refresh this state.

Resize reserves two columns and five rows using saturating subtraction and clamps only nonzero axes. A zero-sized axis can therefore leave an older cursor coordinate in place. Cursor movement casts to `i16` and adds signed deltas before clamping; extreme public values can overflow with checked arithmetic or behave differently in wrapping builds. Zoom tiers are 4096/512/64 with Galaxy/Region/Local labels. Zoom-in stores prior zoom and center (not cursor), moves center to the old cursor voxel, and resets cursor to the midpoint. Zoom-out restores stored zoom/center and midpoint; an empty stack returns false without setting `should_quit` (the input layer owns that policy). Public mutation can make stack and zoom inconsistent. Centering on a known player changes center/cursor while preserving zoom/stack; no player is a no-op.

Geometry uses current zoom extent divided by each grid dimension guarded to at least one; the viewport begins at center minus half extents. `voxel_to_grid` casts float coordinates to integers, which truncates toward zero rather than flooring and is not strict continuous-rectangle containment; nonfinite/extreme values follow Rust cast semantics. There is no range validator. The zero-grid E2 query is written with the actual `f64` signature as `voxel_to_grid(100.0, 200.0)`, returning `None`. Zero-size viewport bounds collapse on that axis. Density mapping is exactly 0→space, 1→`·`, 2–3→`+`, 4–7→`*`, and 8 or more→`#`. The requested E1–E3 examples are literal contract checks, not output-generated expectations: E1 compares the entire state tuple and ordered Alpha/Beta label vector while distinguishing active model galaxy from session galaxy and position-address reality; E2 checks the specified resize, voxel/grid, bounds, movement, zoom-stack, restore, player-center, and zero-grid values; E3 checks the complete zoom tuple array and density input/output arrays.

**W4 — renderer (`render.rs:15–35`, `38–159`, `161–234`, `356–401`).** `render` writes a Ratatui frame from the supplied state/model; it does not manage a terminal, poll input, restore modes, or refresh snapshots. It lays out map/status/legend and paints help last. The map returns early for a zero inner dimension. Systems are binned using `state.galaxy` and X/Z; `state.grid_size` separately drives state/status cursor math and is expected to be synchronized through resize. Stored A–Z base labels render yellow; Local labels add names downward, may collide or overwrite near the last row; the green player marker may overwrite a base, and the cursor uses reverse style. Density colors are fixed, not configurable themes. Local label clipping slices at a byte boundary, so a multibyte name cut can panic; docs must state this actual limitation without changing it.

E4 is an in-memory Ratatui example using pinned `TestBackend` and `Terminal`: resize to 80×24, place the player at (0,0), draw, then inspect the backend buffer. The required full observations are the cell tuple at (40,10) and the complete legend text on row 22 after trimming only trailing padding. The compile-only hidden main must return `Result<(), Box<dyn Error>>` because `TestBackend::Error` is `Infallible`; the terminal entry example separately uses `io::Result`. This demonstrates selected rendered output, not whole-screen or terminal-lifecycle correctness.
