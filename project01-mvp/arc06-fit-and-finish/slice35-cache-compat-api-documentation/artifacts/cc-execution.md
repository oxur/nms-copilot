## Closed contract and implementation scope

The cache archive is a mutable six-field serialized subset, not a full GalaxyModel snapshot: it stores systems with embedded planets, bases, optional supported player state, independently selected galaxy, caller-provided save version, and whole-second cache timestamp. It omits custom topology, derived indexes, orphan flat planets, sessions, complete source JSON and history; extracted HashMap vector order is unspecified and timestamp subsecond precision is lost. The 16-byte envelope is NMSCACHE plus schema 4 and semantic 6 as little-endian u32, followed by checked aligned rkyv data. Direct decoding rejects legacy/mismatched envelopes in length→magic→schema→semantic→payload order, and then validates only duplicated current player reality and marked-placeholder shape. Direct APIs do not source-fallback. Trusted in-memory rebuild is infallible and may preserve malformed marked entries as ordinary systems; it rebuilds derived indexes/default edges and does not itself ensure the player key. write_cache, read_cache, and load_or_rebuild have distinct filesystem/freshness/fallback behavior; the loader’s freshness predicate is strictly cache mtime greater than source mtime and does not inspect content.
