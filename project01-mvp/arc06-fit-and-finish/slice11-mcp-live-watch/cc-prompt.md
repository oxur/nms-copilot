## Binding decisions and implementation recipe

### 1. Keep the watcher alive for the complete server lifetime (LW-01/05)

At e615f254 mcp/mod.rs start_watcher returns `Some(handle.receiver)`; its remaining `_debouncer` field is dropped at that helper's end, cancelling filesystem monitoring. Returning only a receiver does not own monitoring. This is a source-grounded defect; native wire tests must reproduce the consequential failure and prove repair. Private start_watcher must return `Option<nms_watch::WatchHandle>`, preserving existing None and warning/fallback behavior. Both public server entrypoints pass that owned handle to private run_mcp_server. Public spawn_mcp_background/run_headless signatures remain unchanged.

Recommended private route: run_mcp_server owns `mut watcher: Option<WatchHandle>` across the entire serving await. Extract the actual receiver using `watcher.as_mut().map(|handle| std::mem::replace(&mut handle.receiver, std::sync::mpsc::channel().1))`; the replacement is a disconnected unused receiver, while the original WatchHandle retains the private debouncer. Then start the existing delta task with the extracted receiver. Keep the owned watcher in server scope until serving ends; explicitly `drop(watcher)` after the transport match documents release. Early `?`/bind-error returns drop it by RAII. Do not move only receiver into a thread and assume closure capture retains the handle; do not leak/forget it, add a public splitter/accessor, poll files instead of notify, or change nms-watch API.

Retain the delta task JoinHandle locally if started. After normal transport completion drop watcher first (closing producer eventually), then abort the owned async delta task and await cancellation, documenting that the existing blocking bridge ends on producer disconnect. Use a small private RAII abort-on-drop wrapper if needed so early-return paths also cancel the spawned task; no public lifecycle API or shutdown framework. Preserve transport error value/ready signal rather than replacing failure with success. The existing detached synchronous bridge has bounded ownership: it exits on receiver disconnect after guard drop or send failure, not by moving the debouncer into it. Do not synchronously join it on an async worker. Inline tests can check None/missing/invalid startup, a retained handle receiving actual writes, and producer disconnect after owner drop with a bounded recv_timeout. No whole application shutdown redesign.
